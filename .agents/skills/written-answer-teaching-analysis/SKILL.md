# 記述式答案の授業改善分析

目的は、次の授業で変える説明・例題・確認問題を、匿名化された答案の根拠とともに提案すること。採点・生徒向け講評を変更しない。

## 依頼を受けたら

1. `AGENTS.md`、`.agents/GUIDELINES.md`、`docs/written-answer-archive.md` を読み、`npm.cmd run archive:written:health` と `npm.cmd run archive:written:units` でローカルの状態と分析可能な単元を確認する。検証に失敗したら、原本を壊さず原因を調べる。SQLiteは原本から `npm.cmd run archive:written:index` で再生成できる。
2. 単元・授業回・クラス・分析の深さが依頼から分からなければ、一覧の実在する候補を示して短く質問する。基本は **対象単元** と **深さ（概観／標準／精査）** の2点。授業回・クラスが複数ある場合だけ範囲も聞く。5人未満の単元は候補名を示しても人数を表示しない。数学以外の分析意図が明白ならこのskillを押し付けず、目的を確認する。回答待ちの間にデータ鮮度と欠損を確認できる。
3. 回答が来たら分析を続ける。概観は集計と目立つ答案の原画像確認、標準は同一問題版・採点版の提出ペアと観点別変化、精査は対象答案の原画像を広く再確認し、誤りタグの根拠と例外まで検討する。深さを指定されなければ標準を提案する。新しい提出まで含める必要がある場合は既存の承認済み回収経路 `npm.cmd run archive:written:pull` を実行し、`archive:written:health` の結果を確認する。

## 分析上の境界

- 画像と `record.json` が原本。AI書き起こし、採点、`feedback_targets`、自動生成の `observations` は誤り得る測定値として扱う。重要な指摘と例外は画像を照合し、確認した観察は根拠・確信度・確認状態を付けて `.local/` 内のJSONLから `npm.cmd run archive:written:observations -- <ファイル>` で保存できる。
- `attempt_group_key` で同一学習者の提出を結び、`attempt_ordinal` と時刻を確認する。別の問題版・採点基準版・授業回を無条件に合算しない。2回目を出した人だけの改善率と、1回目を出した全員の割合を混同しない。
- 1回目の誤りが2回目で解消した割合と、適切な指摘後も残った割合を、観点タグごとに分母つきで示す。指摘の対象は `feedback_targets` と講評本文を照合する。`exposures` の時刻が1回目と2回目の間なら「画面に表示された」とだけ表現する。表示記録なしは未読の証拠ではない。
- 授業説明不足やAI講評の効果は因果的に断定しない。もともとの理解度、自発的な再考、模範解答の表示、再提出者の選択、採点・書き起こしの誤差を代替説明として検討する。初回説明で補う候補と、再指導が必要な候補を区別する。
- 人数・提出数・ペア数・欠損数・問題版を明記する。小集団（5人未満）は個人を推測できる内訳や原文を共有用出力に載せない。氏名・UID・メールを扱わず、答案画像をクラウドや外部AIへ送らない。

## 出力

対象・データ時点・分析対象に含めた提出を最初に示し、①初回説明で補う候補、②講評後も残る誤り、③追加の有用な発見、④次時の具体的な指導案、⑤証拠の強さと欠損を報告する。数値と匿名化した原画像の読取例を対応させ、未確認タグのみの結論は仮説と明記する。詳しいテーブル関係と集計時の注意は [references/analysis-method.md](references/analysis-method.md) を必要時に読む。
